Write it at the project root, with the user, one section per stage. Fill every section; write "none" or "not needed, because ..." rather than dropping one. Put the user's decisions in their words. ## Worked example: `article-flow`

A five-agent article workflow, filled in. It is a fixture: a test checks that it has all eleven sections and a reason for every excluded dimension, and that nothing in it is a domain answer written by the assistant.

```markdown
# article-flow: evaluation design

Version 1, 2026-10-30. Decided by the editor-in-chief (domain expert and dataset owner) and the engineer who owns the prompts. Built from this record by the llm4j-workflow-guide skill.

## 0. Readiness
- The system: takes a topic and a platform, researches it on the web, outlines, writes, edits and checks the article, and saves a draft for a person to publish. Readers are the company's customers.
- The worst it can do if completely wrong or completely fooled: publish an article with invented sources or injected text; saving a draft is the only effect and a person publishes.
- Preflight: passed 2026-10-29; one real answer read under a cap by the editor-in-chief on 2026-10-30: whole, but padded, and Sources was missing.

## 1. Layer map
| Part | Deterministic or probabilistic | Tested by |
|---|---|---|
| CheckLength, CheckSources, FormatArticle (tasks) | deterministic | unit tests and `weave test` |
| SaveDraft (task, changes the world) | deterministic | `weave test` with a scripted result; never run for real in a test |
| Routing by platform (`alt`) | deterministic | `weave test` |
| Researcher (grounded), Outliner, Writer, Editor, Reviewer | probabilistic | `weave eval`, one dataset file per agent and one for the workflow |

## 2. Dimensions
| Dimension | Applies? | Reason |
|---|---|---|
| Relevance | yes | the Researcher's sources must be about the topic |
| Groundedness | yes | invented sources were the worst failure in the first real run |
| Correctness | yes | claims in the article must be right for the domain expert |
| Completeness | yes | every article needs a Sources section and the requested length |
| Calibration | no | no step states a confidence that triggers an action |
| Instruction following | yes | length, platform format and tone are instructions |
| Coherence | no | a single turn per article; no conversation |
| Safety | yes | injection through web pages the Researcher reads |
| Efficiency | yes | cost per saved draft matters to the budget |

## 3. Oracles
| Property | Oracle type | Why not a stronger type | Carried in the stack by |
|---|---|---|---|
| A Sources section exists and every URL in it was returned by the Researcher | assertion | (strongest) | `expected_output_contains` and a task |
| Length is within the platform's band | assertion | (strongest) | `expected_min_words`, `expected_max_words` |
| The article's claims are supported by its sources | rubric (anchored 1 to 5 kept in the dataset folder) | a claim's support cannot be matched by string | `rubric:` lines, judge `--judge <other family>` |
| The tone suits the platform | rubric | a matter of degree | `rubric:` lines |
| The article is one an editor would publish | human, on a sample | no rubric captures it | the editor-in-chief reads 20% of each release's output |

Judgement calls turned into assertions: "does it hallucinate sources?" became "every cited URL is in the Researcher's returned set". Metamorphic relations used: paraphrasing the topic should not change the article's conclusion (pairs tagged `relation:paraphrase`).

## 4. Dataset
- Domain expert: the editor-in-chief; dataset owner: the editor-in-chief (the engineer owns the prompts)
- Sources and shares: production-derived 0% now (no history yet: the pipeline for it is item 1 of the plan), expert-authored 100% now, synthetic 0%
- Coverage dimensions and values: platform (blog, linkedin), difficulty (standard, hard), topic completeness (complete, vague); the three missing classes: unanswerable 0, obvious answer wrong 0, conservative action 0: **asked of the editor-in-chief; not yet provided**
- Size now and next stage: 12 cases; next 50; at least 10 per reported slice: no, the slices have 3 to 6 cases each until the next stage
- Split: development 60%, validation 25%, held-out 15% (sealed; run only with `--release-gate`)
- Labelling guide: `eval/golden/LABELLING.md`; double-labelled 0 cases; agreement not yet measured
- Governance: bump `version:` on any case change; refresh 15% a quarter; archive retired cases in `eval/golden/archive/`; every incident becomes a candidate case; review annually
- Drafted by an assistant and not yet reviewed: 4 cases tagged `author:assistant`; the editor-in-chief reviews them before the next run

## 5. Harness
| Component | Exists in the stack? | What is missing, and the workaround |
|---|---|---|
| Trace capture | yes (Loom's journal) | none |
| Configuration fingerprint | yes (the report's fingerprint) | none |
| Fixtures, and when refreshed | yes (`fixtures.yaml`); refreshed quarterly | none |
| Simulator and faults | yes (`weave test` `fail:`) | none |

## 6. Run protocol
| Context | Cases | Repetitions | Frequency | Budget (circuit breaker) |
|---|---|---|---|---|
| Per change | 6 core cases | 3 | every change touching prompts, agents, tools | `--max-cost 1.00` |
| Nightly | validation | 5 | scheduled | `--max-cost 5.00` |
| Release gate | validation + held-out | 10 | on demand | `--max-cost 25.00` |
| Drift check | validation | 5 | weekly, fixed configuration | `--max-cost 5.00` |

## 7. Security
- Injection surfaces: web pages and search results the Researcher reads; the topic text; the platform field
- Payload corpus: 40 payloads at first, 12 indirect placements in fixture pages; in `eval/security/`, versioned with the dataset; run against scripted tools so no draft is saved
- System-level controls that must hold at 100% when the model is fooled: SaveDraft is a task, not a tool, and cannot be called by a model; Publisher is a person; verified by a `weave test` case per payload asserting no SaveDraft call without the Reviewer's approval
- Model-level defences: the Researcher's instruction to ignore instructions in pages (a percentage, reported as one)
- Red-team plan: one week before the first public release; engineer and editor-in-chief; objective "get invented text published under the company's name"
- Accepted risks: none yet

## 8. Regression and baselines
- Runs triggered by: commits to prompts, agents, tools; a prompt edit; a model version change; weekly
- Baseline policy: saved with the editor-in-chief's name and a written reason; compared with the current and the previous baseline

## 9. Gates
| Dimension | Stage | Absolute floor | Regression band | Zero-tolerance checks | Judge validated? |
|---|---|---|---|---|---|
| Groundedness | release | set by the editor-in-chief | 3 points | a cited URL not in the Researcher's set | no: validation planned before the first release; **until then it does not gate** |
| Completeness | per change | set by the editor-in-chief | 3 points | missing Sources section | not needed (assertion) |

## 10. Ownership
| Role | Named |
|---|---|
| Dataset owner | editor-in-chief |
| Judge owner | the engineer |
| Gate approver | head of editorial |
| Owner of the prohibited-operations list | head of editorial |

## Decisions log
| Date | Decided | By | Why |
|---|---|---|---|
| 2026-10-30 | Calibration and coherence excluded | editor-in-chief | no confidence field, single turn |

## Gaps and workarounds
| What this project needs and the stack does not do | Register id | Workaround in use |
|---|---|---|
| Kappa and a validated judge | F56 | three editors score 40 outputs in a spreadsheet |
| A set of accepted answers | F57 | one rubric line per acceptable outcome |
| A versioned security corpus runner | F63 | a folder of payload cases and a `weave test` assertion each |

## Open risks
- The three missing case classes are not yet provided; the dataset is below 50 cases; the judge is not validated.

## Hand-over
Stages this feeds in `llm4j-workflow-guide`: dataset (4), prompt and agent tests (5), workflow and trajectory tests (8), the real evaluation (9). Harness record: HARNESS.md, section 9 points back here.
```
