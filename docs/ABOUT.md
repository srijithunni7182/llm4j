# About llm4j

[← Back to the README](../README.md)

## Mission

**Bring generative AI development closer to Java developers.**

Java runs the systems that can't go down, yet most agent tooling assumes Python. llm4j sets out to make building with
LLMs feel like ordinary Java: an agent is an object you construct with a builder, test with JUnit and bound with a budget.

Three ideas shape everything in the repository:

1. **Simplify the plumbing.** Retries, budgets, tool calls, approvals, checkpoints, resuming a run and fanning out to
   several agents are the same work in every project. Loom, the workflow DSL, takes them over, so a multi-agent
   workflow is a short `.loom` script and not a few thousand lines of glue code.
2. **Stay lightweight.** There are no vendor SDKs and no application framework. `ai-agent4j` talks to Gemini, Claude,
   OpenAI, xAI, Perplexity, Kimi, Qwen, Sarvam, Ollama and any OpenAI-style server over plain HTTP behind one contract. Its core runtime needs only a handful of well-known libraries
   (Jackson, OkHttp, SLF4J, Swagger Parser, Commons Math and jsoup). It does not require Spring, and it runs on Java 17+.
3. **Make agents trustworthy.** Evaluation (eval4j), audit trails, confidence scores, PII masking, spend caps and
   security checks (`weave audit`) ship with the stack, and so does web search with typed citations and a search budget
   (`Grounding`, `grounding: web` in Loom).

## The stack

| Piece | What it does |
|---|---|
| **ai-agent4j** | Agents, tools, skills, memory, RAG and the provider contract |
| **Loom** | The DSL, the `weave` CLI, a VS Code extension, and live observability (loom-inspect and Fabric) |
| **eval4j** | Evaluation and testing for agents in plain JUnit, plus a local report dashboard |
| **Engram** | The memory engine behind long-running workflows |

See [The stack](THE_STACK.md) for how they fit together.
