# LR11: `label` acts on what agent `proseAgent` wrote (`proseVariable`), and nothing checks it on the way

- **Lens:** Reliability
- **Severity:** medium
- **From:** the core rule pack
- **Applies to:** each step
- **Since:** core 6.2.0

Fires when text an agent wrote freely (no output_schema, no expecting) reaches, directly or through set and interpolation, a step that changes something: a delegate to an agent that holds a tool whose effect is changes and is not under approve:, or a use of such a tool without approve. It stays quiet when a step that checks the text stands between: an extract, an intentclassify, a run of a task that reads it, a check against a policy, a decide, or approve on the acting step. Only structure is read (value flow, tool effects, statement kinds), never what a prompt means.

Why it matters: If the first agent invents a fact (an amount, an order id), the second acts on it with confidence. The mistake travels downstream and becomes an action.

What to do: Check the hand-off with the cheapest thing that works: extract the fields and test them (alt, or a task), check the text against a policy, or add approve to the acting step.

## When it fires

`actsOnUnvalidatedProse is true`

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LR11 = off` in `review.properties` turns the rule off, and `LR11.severity = low` changes how loud it is.
