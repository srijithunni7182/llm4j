# LR12: `label` ends when agent `loopDecider` says it is done, and `loopDecider` also wrote the work

- **Lens:** Reliability
- **Severity:** medium
- **From:** the core rule pack
- **Applies to:** each step
- **Since:** core 6.2.0

Fires on a loop whose condition reads the answer of a delegate in the loop body to an agent that also produces the work the loop iterates on: the same agent binds another variable that is read later, or the agent is handed its own answer again on the next round. It stays quiet when a different agent reviews, when a task or a check decides, or when a person does. Only structure is read (who binds what, what the condition reads), never what a prompt means. Rewind conditions are not read yet, and the add-reviewer fix is not built.

Why it matters: An agent that decides its own work is finished tends to say yes. The loop stops when the writer is satisfied, not when the work is good.

What to do: Let a different agent review it (starter 03's shape), check the criteria in code with a task (best when they can be checked, such as tests passing), or check the text against a policy.

## When it fires

`decidesItsOwnLoop is true`

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LR12 = off` in `review.properties` turns the rule off, and `LR12.severity = low` changes how loud it is.
