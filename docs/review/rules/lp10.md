# LP10: Agent `name` reasons (`reasonsBecause`) and must answer in a schema with `largeSchemaBecause`

- **Lens:** Prompts
- **Severity:** medium
- **From:** the core rule pack
- **Applies to:** each agent
- **Since:** core 6.2.0

The runtime asks an agent with an output_schema to reply in JSON only. That is fine for a small, flat verdict from an agent that does not need to think. It is a trap for an agent that reasons (it has tools, searches the web, works over rounds, or has a long prompt) and must fill a large schema (a nested object, a list of objects, or more than prompts.large-schema-fields fields, default 5). Let the agent write its analysis as prose, then use an extractor to pull the fields out of that prose. The rule reads the structure of the script; a prompt whose size cannot be read is not judged on size.

Why it matters: An agent told to answer in JSON only has no room to think in its answer, so it makes logical leaps or breaks the format. The thinking and the formatting are two jobs.

What to do: Let the agent answer in prose, and pull the fields out with an extractor; or make the schema small and flat; or accept the finding with a reason.

## When it fires

`reasons is true and largeSchema is true`

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LP10 = off` in `review.properties` turns the rule off, and `LP10.severity = low` changes how loud it is.
