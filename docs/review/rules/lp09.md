# LP09: Agent `name` pulls fields out of text

- **Lens:** Prompts
- **Severity:** medium
- **From:** the core rule pack
- **Applies to:** each agent
- **Since:** core 6.2.0

The rule looks at the structure of the script: an agent with an output_schema, has no tools, no grounding and no memory block, a short prompt (prompts.short-prompt-tokens in review.properties, default 300), and every delegate to it passes at least one variable. It does not read what the prompt means. Only an agent with its own output_schema counts: an agent whose answer shape is given per step with expecting is used in several ways, and is not an extractor by structure. Neither is an agent whose whole schema is one enum field: that picks a label, which is a classifier's job, not an extractor's. If the agent really needs the conversation, give it a tool or a memory block, or accept the finding with a reason.

Why it matters: An agent is briefed with the whole run so far and the shared prompt, so what it extracts can depend on what ran before it. An extractor does the same job without seeing either.

What to do: Declare an extractor with the same fields and use extract instead of delegate (weave review --fix-finding LP09 shows the rewrite).

## When it fires

`hasSchema is true and choosesOneLabel is false and hasTools is false and grounded is false and hasMemory is false and promptTokens <= the setting prompts.short-prompt-tokens and delegatesPassVariables is true`

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LP09 = off` in `review.properties` turns the rule off, and `LP09.severity = low` changes how loud it is.
