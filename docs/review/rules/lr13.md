# LR13: `label` walks over `fanoutList`, a list a model wrote, with no maximum

- **Lens:** Reliability
- **Severity:** medium
- **From:** the core rule pack
- **Applies to:** each step
- **Since:** core 6.2.0

for each ... max N fails the workflow before any item starts when the list is longer than N, and names the agent that wrote the list, because a list far over its bound usually means a problem upstream: what the agent was given, what it was asked, or text in its input trying to steer it. The rule fires only for a list an agent or extractor wrote; a list passed in by the caller is not model-written. The cost estimate shows the worst case of such a step as unknown until it has a maximum.

Why it matters: The length of the list is chosen by a model (or by text that steered it), so this step may run once for every item of a list of any length. Budgets stop the total, but they stop it part-way, with some items done.

What to do: Add max N after the list (and tell the agent that wrote it the limit in its instructions). Add on_too_many { ... } if something other than failing should happen.

## When it fires

`kind is foreach and fansOutModelList is true and fanoutBound is 0`

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LR13 = off` in `review.properties` turns the rule off, and `LR13.severity = low` changes how loud it is.
