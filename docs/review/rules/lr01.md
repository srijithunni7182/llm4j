# LR01: `label` has a tool but no retry or timeout

- **Lens:** Reliability
- **Severity:** medium
- **From:** the core rule pack
- **Applies to:** each step
- **Since:** core 1.0.0

A delegate to an agent that has tools can fail in ways a plain model call does not: a tool times out, an API rate-limits, a network drops. A retry gives the step another chance and a timeout stops one call from holding the run forever. The fix adds the retry and timeout your project prefers (fix.retry in review.properties).

Why it matters: A tool call can fail or hang. Without a retry and a timeout one slow or failing call stalls or ends the whole run.

What to do: Add a retry and a timeout to this step.

## When it fires

`kind is delegate and agent.hasTools is true and retry is false and timeout is false`

## Fix

`weave review --fix` applies: Add retry and timeout.

## Options

`weave review --assist` offers these, and you choose and give the values.

- **retry-timeout**: Retry and time out. A failed or slow call is tried again, up to the number of tries, then the step fails. If the agent writes or sends, a retry can repeat the action. Asks: Retry policy (default `retry 2 backoff 2s timeout 60s`).
- **timeout-only**: Time out only, no retry. A call that takes too long is cut off and the step fails once; nothing is repeated. The right choice when the agent sends or writes. Asks: Time out after how many seconds (default `60`).

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LR01 = off` in `review.properties` turns the rule off, and `LR01.severity = low` changes how loud it is.
