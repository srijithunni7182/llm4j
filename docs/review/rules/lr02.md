# LR02: `label` can write or send but has no on_failure

- **Lens:** Reliability
- **Severity:** medium
- **From:** the core rule pack
- **Applies to:** each step
- **Since:** core 1.2.0

An agent whose tools write or send can fail after part of its work is done. An on_failure block is where the workflow says what then: stop cleanly, tell someone, or ask a person. Without one the failure ends the run wherever it happens.

Why it matters: When a step that acts on the outside world fails half way, nothing decides what happens next: the run ends with the effect done, undone or unknown.

What to do: Add an on_failure block that records the failure and asks a person what to do.

## When it fires

`kind is delegate and agent.hasEffects is true and onFailure is false`

## Fix

`weave review --fix` shows (and applies only with `--yes`): Add an on_failure block that records the failure.

## Options

`weave review --assist` offers these, and you choose and give the values.

- **note**: Record the failure and carry on. The failure is written to the run's notes and the workflow continues with the next step. Only right if later steps can work without this one's result. Asks: What the note should say (default `this step failed`).
- **human**: Ask a person what to do. The run pauses and a person is asked; their answer is kept in a variable. Use this when the failure leaves something half done that only a person can judge. Asks: What to ask the person (default `This step failed. Check it, then answer done.`); Variable that keeps their answer (default `checked`).

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LR02 = off` in `review.properties` turns the rule off, and `LR02.severity = low` changes how loud it is.
