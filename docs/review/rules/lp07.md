# LP07: The text of `label` contains the variable name '`payloadHitsVariable`', which Loom fills in

- **Lens:** Prompts
- **Severity:** medium
- **From:** the core rule pack
- **Applies to:** each step
- **Since:** core 1.3.0

Older scripts wrote a variable's bare name in a prompt and Loom still honours that: the name is replaced everywhere in the literal text of the prompt, with no regard for word boundaries. The safe form is {name}. A short or common name (r, a, result, text) makes the old form fire on words that happen to contain it. This was found measuring costs against a real provider: a variable named r multiplied one prompt by the length of an earlier answer.

Why it matters: Loom replaces a bare variable name wherever it appears in the text a script wrote, even inside another word. A variable called r rewrites every r in the sentence with the variable's value, which changes the prompt and can make it huge.

What to do: Rename the variable to a longer name that does not occur in the text, and put the value in curly braces around its name.

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LP07 = off` in `review.properties` turns the rule off, and `LP07.severity = low` changes how loud it is.
