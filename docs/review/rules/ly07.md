# LY07: Text a model wrote leaves the workflow and the script declares no policy

- **Lens:** Privacy and compliance
- **Severity:** medium
- **From:** the core rule pack
- **Applies to:** each script
- **Since:** core 6.2.0

A prompt is a wish, not a guarantee, so rules about what must never be said belong in a policy file (policies/house-rules.md, written for whoever owns compliance) and are checked at the edge by an evaluator that sees only the rules and the text. Declaring a policy also makes the runtime refuse any model-written text that has not been checked, at the return of the run and in what an agent sends. The rule fires once per script and lists the exits it found. It fires only when the output can reach people outside: the workflow is scheduled, or an agent holds a tool that changes things. A script with no such reach is not nudged. Review and accept it with a reason when no customer sees the output.

Why it matters: Nothing judges what a model wrote before it reaches people: {modelTextExitList}. A reply that quotes an internal section or promises something it should not goes straight out.

What to do: Put the rules in a policy file, declare an evaluator and check the text before each exit: check reply against HouseRules using Compliance. If no customer sees this output, accept the finding with a reason.

OWASP LLM Top 10: LLM02, LLM05, LLM07

## When it fires

`declaresPolicy is false and modelTextExitCount >= 1 and reachesPeople is true`

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LY07 = off` in `review.properties` turns the rule off, and `LY07.severity = low` changes how loud it is.
