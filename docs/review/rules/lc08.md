# LC08: `label` does not use the answer of the step before it and could run beside it (saves about `parallelSavingSeconds` s)

- **Lens:** Cost and performance
- **Severity:** low
- **From:** the core rule pack
- **Applies to:** each step
- **Since:** core 1.6.0

Loom steps run in order, and by default each one sees what the steps before it said. Steps that are independent (the second does not mention the first one's variable, and neither agent has a tool that writes or sends) can run in a parallel block, which takes the time of the longer one. The saving shown is the shorter of the two, from the latency assumptions (assume.latency.small|standard|large). Because parallel branches do not see each other's answers, the review leaves the change to you.

Why it matters: Two steps that need nothing from each other, and that do not write or send, take the sum of their times when they run one after the other and only the longer when they run side by side.

What to do: Put the two steps in a parallel { } block. They then no longer see each other's answers in the shared conversation, so check that neither needs to.

## When it fires

`kind is delegate and parallelizableWithPrevious is true`

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LC08 = off` in `review.properties` turns the rule off, and `LC08.severity = low` changes how loud it is.
