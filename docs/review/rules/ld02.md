# LD02: Tool `name` is your own Java: a resumed run can repeat what it does

- **Lens:** Durability
- **Severity:** high
- **From:** the core rule pack
- **Applies to:** each tool
- **Since:** core 1.0.0

When a run is stopped by a crash or a restart and resumed, the steps that finished are replayed from the journal instead of being done again. That holds for effects the runtime knows about (webhook, email, http, file, shell, sql) and for run tasks. It cannot hold for a Java class the runtime never looks inside. If the class sends or writes, resuming can do it twice.

Why it matters: Only the built-in tool kinds and run tasks journal their effects. A resumed or retried run can call your Java tool a second time and repeat what it did, such as sending the same message twice.

What to do: Move the effect behind a run task, use a built-in kind that journals, or make the tool safe to repeat and say so.

OWASP LLM Top 10: LLM06

## When it fires

`kind is class and reachKnown is true and reach is one of [writes, sends] and idempotentDeclared is false and number of usedBy > 0`

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LD02 = off` in `review.properties` turns the rule off, and `LD02.severity = low` changes how loud it is.
