# LR10: `label` repeats work that writes or sends, and no checkpoint comes before it

- **Lens:** Reliability
- **Severity:** info
- **From:** the core rule pack
- **Applies to:** each step
- **Since:** core 1.6.0

Checkpoints name the places a rewind can return to. A loop that writes or sends and may turn five times or more, or has no maximum, is the kind of work where going back to just before it is useful. This is advice, so it is INFO.

Why it matters: A rewind can only go back to a checkpoint. With none before a long loop that acts on the world, the only point to go back to is the start of the workflow, before everything the loop already did.

What to do: Put a checkpoint before the loop, so a rewind can return to just before it.

## When it fires

`kind is loop and loopBodyHasEffects is true and checkpointBefore is false and (hasMax is false or loopMax >= 5)`

## Handle it without editing code

`weave review --accept FINGERPRINT --reason "why"` records that the finding is fine. `LR10 = off` in `review.properties` turns the rule off, and `LR10.severity = low` changes how loud it is.
