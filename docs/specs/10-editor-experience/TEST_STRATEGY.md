# Phase 10 test strategy: the editor experience

Status: **draft for review**. Requirements `R1`…`R41` are in [DESIGN.md](DESIGN.md); the traceability matrix is in [VERIFICATION.md](VERIFICATION.md).

## 1. Principles

- **The engine is faked in extension tests; the extension is faked in engine tests.** Extension logic is tested against an `EngineClient` fake with canned JSON (real JSON produced by the real engine and stored as fixtures, regenerated by a script). The server is tested in JUnit over real pipes. One integration layer runs the real jar against the real extension code path.
- **Existing patterns are reused:** `fakeVscode.ts`, node:test, the Playwright-in-node browser tests (skipped with a clear message when no browser), the `webview.browser.test.js` style.
- **The data is the oracle for the panel.** A page test asserts what a person reads (words, counts, order, which element is focused, which node is selected) and that numbers equal the JSON, never pixels.
- **Time is injected.** Debounce, timeouts and restarts use a fake clock; no test sleeps.
- **Old behaviour is pinned.** The existing check/graph/LSP tests run unmodified; the graph panel and Problems output are compared before and after routing through `EngineClient`.
- **Hostile text is data.** Rule titles, agent names, prompt text and file names containing markup, RTL text, control characters and 10,000-character lines render as text.

## 3. Fixtures

- `test/fixtures/review/*.json`: real engine output for 12 scripts (clean, one flaw per lens, many flaws, unbounded cost, script-level finding, 300 findings). Regenerated by `scripts/regen-editor-fixtures.sh`, never hand-edited.
- `test/fixtures/workspaces/`: small projects with imports, prompts, a `review.properties`.
- A `FakeEngine` with scripted latency and failures; a `FakeClock`.

## 4. Fault injection

Engine killed mid-request; engine replies after a newer request was issued; engine replies for an old version; malformed JSON frame; a partial frame split across chunks; a frame larger than 16 MB (refused); `review.properties` becomes invalid while open; file deleted while the panel is open; a fix whose target text changed since the review (the editor must refuse and re-run); two windows on one workspace.

## 5. What is deliberately not tested

- Pixel layout and colour values (contrast is computed from tokens, not from screenshots).
- VS Code's own rendering of CodeLens, status bar and lightbulb (we test what we hand to the API).
- Other editors (out of scope).
