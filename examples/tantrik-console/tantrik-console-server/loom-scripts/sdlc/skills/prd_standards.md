# PRD Standards
- Start from the user's problem, not the solution; state who has it and how often.
- Every functional requirement is testable: one behaviour, one "shall", measurable acceptance criteria.
- Separate goals from non-goals explicitly; non-goals prevent scope creep.
- Non-functional requirements carry numbers (latency, availability, data retention), never adjectives.
- Mark assumptions and open questions instead of guessing.
